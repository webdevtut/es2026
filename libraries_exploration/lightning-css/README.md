# Lightning CSS Landing Page

A responsive, static landing page demonstrating **Lightning CSS** as a CSS compiler/bundler and **CSS Modules** for locally scoped class names.

## What this demonstrates

- **CSS Modules:** source class names are compiled to unique names.
- **CSS nesting:** nested selectors are transformed into browser-ready CSS.
- **Custom media queries:** `@custom-media` is enabled as a draft feature.
- **Minification:** production CSS is minified at build time.
- **Scoped identifiers:** CSS custom properties, animations, grid identifiers, and custom identifiers can be scoped through CSS Modules options.
- **Static output:** generates `dist/index.html` and `dist/styles.css`; no frontend framework or runtime JavaScript is required.

> Lightning CSS is a CSS parser, transformer, bundler, and minifier. This example uses its JavaScript `transform()` API for a single CSS Module. Its CLI can also bundle CSS `@import` dependencies into one stylesheet.

## Requirements

- Node.js 18+ recommended
- npm

## Run the project

```bash
npm install
npm run build
```

Then open `dist/index.html` in a browser, or serve the `dist` directory with any static file server.

For example, if you have a static server installed:

```bash
npx serve dist
```

## How CSS Modules are wired

1. `index.html` uses readable source class names such as `hero`, `featureCard`, and `primaryButton`.
2. `scripts/build.mjs` passes `main.module.css` to Lightning CSS with `cssModules` enabled.
3. Lightning CSS returns compiled CSS plus an `exports` map from each source class to its generated name.
4. The build script rewrites class names in the HTML using that map and writes both files to `dist/`.

This is a small static-site example. In a framework or JavaScript bundler, the generated class mapping is usually imported/consumed by the application build system instead of rewritten in HTML.

## CSS Modules options used

```js
cssModules: {
  pattern: "[name]_[hash]_[local]",
  dashedIdents: true,
  animation: true,
  grid: true,
  customIdents: true
}
```

- `pattern`: controls generated local names. Supported placeholders include `[name]`, `[hash]`, `[content-hash]`, and `[local]`.
- `dashedIdents`: scopes custom identifiers such as CSS custom properties.
- `animation`: scopes animation names.
- `grid`: scopes grid line names and areas.
- `customIdents`: scopes other custom identifiers.

The build also enables modern syntax transforms:

```js
drafts: {
  nesting: true,
  customMedia: true
}
```

## CLI alternative: bundle and minify CSS imports

For a conventional CSS-only pipeline, Lightning CSS provides a CLI package:

```bash
npm install --save-dev lightningcss-cli
```

Example script:

```json
{
  "scripts": {
    "build:css": "lightningcss --minify --bundle --targets \">= 0.25%\" src/styles/main.css -o dist/styles.css"
  }
}
```

The CLI supports CSS Modules with `--css-modules`, but a static HTML page also needs the generated class-name mapping. This repository uses the JavaScript API so that the HTML can be rewritten with the exact generated names.
