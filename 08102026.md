# Immer with TypeScript

Immer lets update code use familiar mutable operations while keeping the
application state immutable. `produce` gives a recipe a writable draft, then
returns the next state without changing the original.

Install Immer with `npm install immer`, then import `produce` and any types or
helpers the examples use.

## Readonly state with writable drafts

**Use case:** Keep application state read-only everywhere except inside an
Immer recipe. This makes accidental mutations outside an update easier for
TypeScript to catch.

```ts
import { produce } from "immer";

type Todo = {
  readonly id: number;
  readonly title: string;
  readonly done: boolean;
};

type State = {
  readonly todos: readonly Todo[];
};

const state: State = {
  todos: [{ id: 1, title: "Read the guide", done: false }],
};

const nextState = produce(state, (draft) => {
  // Draft removes readonly modifiers, so normal assignment is safe here.
  draft.todos[0].done = true;
  draft.todos.push({ id: 2, title: "Try the examples", done: false });
});

// `state` is unchanged; `nextState` contains the updates.
console.log(state.todos[0].done); // false
console.log(nextState.todos[0].done); // true
```

## Reusable typed recipes

**Use case:** Let a store or component accept update logic without exposing its
state as mutable. A recipe can either edit its draft or return a replacement
state.

```ts
import { produce, type Draft } from "immer";

type Recipe<S> = (draft: Draft<S>) => void | S;

function updateState<S>(
  setState: (updater: (previous: S) => S) => void,
  recipe: Recipe<S>,
): void {
  // Run the recipe against the latest state rather than a captured old value.
  setState((previous) => produce(previous, recipe));
}
```

### React state example

**Use case:** Share typed update recipes across event handlers while retaining
React's functional state updates.

```tsx
import { useCallback, useState } from "react";
import { produce, type Draft } from "immer";

type Profile = {
  readonly name: string;
  readonly notificationsEnabled: boolean;
};

type ProfileRecipe = (draft: Draft<Profile>) => void | Profile;

export function ProfileSettings() {
  const [profile, setProfile] = useState<Profile>({
    name: "Ada",
    notificationsEnabled: true,
  });

  const updateProfile = useCallback((recipe: ProfileRecipe) => {
    // React supplies the latest profile; Immer makes only the draft writable.
    setProfile((previous) => produce(previous, recipe));
  }, []);

  return (
    <button
      type="button"
      onClick={() =>
        updateProfile((draft) => {
          // Event handlers can express a focused change without mutating state.
          draft.notificationsEnabled = !draft.notificationsEnabled;
        })
      }
    >
      Notifications: {profile.notificationsEnabled ? "on" : "off"}
    </button>
  );
}
```

## Curried producers and extra arguments

**Use case:** Create a reusable state updater that can be passed to a setter or
called with a state and an action value.

```ts
import { produce, type Immutable } from "immer";

type Todo = Immutable<{
  title: string;
  done: boolean;
}>;

// The tuple declares the extra argument accepted by this curried producer.
const setTodoDone = produce<Todo, [done: boolean]>((draft, done) => {
  draft.done = done;
});

const todo: Todo = { title: "Review changes", done: false };
const completedTodo = setTodoDone(todo, true);

console.log(completedTodo.done); // true
```

If inference is unclear for a curried producer, specify its state type. When
the producer has extra arguments, specify their types as a tuple as above.

## Bridging readonly values with `castDraft`

**Use case:** Assign a readonly collection from the base state to a writable
draft field. TypeScript correctly rejects this assignment without an explicit
cast because the readonly collection does not expose mutable array methods.

```ts
import { castDraft, produce } from "immer";

type Todo = {
  readonly title: string;
  readonly done: boolean;
};

type TodoLists = {
  readonly finished: readonly Todo[];
  readonly unfinished: readonly Todo[];
};

function finishAll(state: TodoLists): TodoLists {
  return produce(state, (draft) => {
    // castDraft is a type-level hint; it does not copy or mutate the input.
    draft.finished = castDraft(state.unfinished);
    draft.unfinished = [];
  });
}
```

## Exposing an immutable result with `castImmutable`

**Use case:** An existing mutable type can remain in use at an API boundary,
while a particular result is explicitly treated as immutable by TypeScript.

```ts
import { castImmutable, produce, type Immutable } from "immer";

type MutableState = {
  todos: { title: string; done: boolean }[];
};

const initialState: MutableState = {
  todos: [{ title: "Ship the feature", done: false }],
};

const nextState: Immutable<MutableState> = castImmutable(
  produce(initialState, (draft) => {
    // produce accepts mutable draft operations and leaves initialState intact.
    draft.todos[0].done = true;
  }),
);
```

`castDraft` and `castImmutable` are runtime no-ops. Use them to communicate the
intended type at a boundary, not as a substitute for validating or copying
data.
